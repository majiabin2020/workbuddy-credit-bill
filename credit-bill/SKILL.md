# WorkBuddy 积分账单（credit-bill）

为本机 WorkBuddy 生成一份**积分账单**（单文件自包含 HTML，离线可看，无外部依赖）。它回答小白用户最关心的问题：**积分到底花在哪了**——哪些模型消耗得多、每个任务消耗了多少、每一笔花在哪几步，全部一笔一笔列清楚。账单同时讲明白一个反直觉的事实：积分多少不只看模型倍率，更看任务实际烧了多少 token——agent 每一轮思考、每一次读文件、每一次调用工具或技能，返回结果都会塞回上下文跟着下一轮请求再发一遍，token 越滚越多，倍率再低也照样烧出高积分。支持每日定时自动刷新 + 资料库固定入口，做到"随时都有一份最新账单"。

## 执行步骤

1. **确认数据目录**：默认 `~/.workbuddy/projects`（Windows / macOS / Linux 通用）。若用户想看其他目录的日志，用 `--projects` 参数传入。
2. **选择 Python**：优先使用平台的托管 Python 运行时；没有则用系统 `python3`（Windows 为 `python`）。脚本仅依赖标准库（3.8+），**无需安装任何依赖**。
3. **运行脚本**（scripts 与 SKILL.md 同目录，用绝对路径调用）：

   ```
   python <skill目录>/scripts/gen_report.py --out <工作区>/credit-bill.html
   ```

   - 默认输出 `credit-bill.html` 到当前目录；完整明细默认嵌入近 30 天的会话，`--days 0` 嵌入全部，`--full` 展示不截断的思考与工具返回原文。
   - 数据目录不存在时脚本会报错退出并提示，此时告知用户本机可能未使用过 WorkBuddy。
4. **展示结果**：用文件展示工具打开发出的 HTML，并用一两句口语汇报关键数字：本期积分总支出、消费笔数、花最多的模型是谁（标称倍率多少、实际每百万 token 多少积分）、花最多的任务/会话是哪一笔。

5. **首次使用时建立固定入口 + 每日自动刷新（默认执行，勿遗漏）**：客户端左侧导航栏无法加自定义入口（官方无此机制），"随时都有一份最新账单"靠**资料库固定页面 + 定时自动化**实现：
   - **固定入口（资料库在线 page）**：首次生成账单后，用 WorkBuddy 内置「资料库」skill 的 `page/import_html.py` 把 HTML 导入为在线页面（`--file-name "WorkBuddy积分账单 <YYYY-MM-DD>.html"`，默认落「我的文档」），**记录返回的 `node_block_id`**。此后该用户每次刷新都对**同一节点**做两步：① `import_html.py --node-block-id <该id>` 重导入覆盖（同一节点新版本，链接不变；注意实测**重导入传 `--file-name` 不会改节点标题**，别指望靠它改名）；② `space_api.py space.workspace.rename-node --node-id <该id> --title "WorkBuddy积分账单 <当天YYYY-MM-DD>"` 更新日期标题。日期标题同时是健康信号：**标题日期 = 最近一次成功刷新日**，日期落后即说明当天自动化没跑成，用户一眼可判断。固定入口即左侧菜单「资料库 → 我的文档 → WorkBuddy积分账单 <日期>」。导入前先过资料库 skill 的图片托管自检（本账单为自包含 SVG，通常无 `<img>` 外链，直接通过）。
   - **每日自动刷新自动化**：固定入口建好后，**主动创建**一个循环自动化（无需再问用户，属于本 skill 的标准交付物）：
     - **名称**：`积分账单每日刷新`
     - **计划**：每天 09:00 循环执行
     - **内容**：① 重跑 `gen_report.py` 输出到同一 `credit-bill.html`（固定路径）；② 走资料库 skill 鉴权后对固定节点做"重导入覆盖 + `rename-node` 更新日期标题（WorkBuddy积分账单 <当天YYYY-MM-DD>）"；③ 用文件展示工具打开本地账单并简要汇报关键数字（本期积分总支出、消费笔数、TOP 模型及其标称倍率与实际积分率、花最多的三笔消费），附固定入口链接；失败时报告报错原因（最多重试 2 次），不要用旧文件冒充新账单，失败当天**不改标题日期**（让日期停留在上次成功日，作为未刷新信号）
     - **防重复**：创建前先列出已有自动化，若已存在同功能的刷新任务则改用它（更新内容即可），不要建第二个
   - **防堆积（硬规则）**：整个生命周期**只允许存在一个**「WorkBuddy积分账单」page 节点——每日同步一律走"重导入覆盖 + rename-node 改标题"，**绝不新建节点**。重导入失败或 `node_block_id` 失效（节点被用户手动删除等）时，**禁止**用"新建节点"当兜底（会一天一个越堆越多，且资料库无删除节点的正式 Agent API，堆了无法自动清理），必须报告用户、说明原因并等待指示；确认节点确已不存在需重建时，先向用户说明旧节点已不在、将建立唯一新节点并重记 `node_block_id`。每次同步成功后可用 `space.searcher.search-nodes` 搜"积分账单"自查，发现多个同名节点（异常情况）须提醒用户手动清理到只剩最新一个。另：page 历史版本是资料库内部版本记录，不出现在文件列表，不算垃圾，无需清理。
   - **注意**：`node_block_id` 是按用户隔离的，必须用**该用户本人**首次导入返回的 id；自动化 prompt 里要写全 gen_report.py 绝对路径、输出路径、node_block_id 与资料库重导入/改名命令，保证无人值守可执行。客户端没有自动化/资料库能力时（如仅本地 CLI 环境），告知用户可手动建每日任务，内容照抄上面的任务描述

## 账单能力

- **本期账单总览（KPI）**：积分总支出（官方逐请求真实积分，与 App 账单同源）/ 消费笔数（会话）/ 请求步骤 / Token 合计 / 思考 token / 缓存命中率
- **「积分是怎么被一步步消耗掉的」图解**：请求生命周期流程图（提问→思考→调工具→回填→回环）+ 上下文滚雪球柱 + 积分公式卡 + 本机真实账单例证（消耗最多的模型 vs 实际最省的模型），一张图看懂积分账
- **WorkBuddy 积分都花在哪些模型上了**：按模型列步骤数、token 构成（输入/缓存命中/思考/输出）、累计积分、**实际积分/百万 token**，与**标称倍率**并列（倍率实时抓官方文档，失败回退缓存/内置表）
- **积分被哪些工具消耗得多（调用 TOP10）**：先按五类分色汇总（内置工具/Skill/MCP/多代理/联网），再按具体名称列 TOP10，工具回填是 token 涨得快的主因之一
- **每个任务消耗的积分是多少？积分消费明细清单**：每笔含时间/标题/工作空间/请求步骤/积分/模型/主要工具，近 7/30/90 天与全部窗口过滤，**可按积分排序（多→少，免积分的排最后）**，点任意一行看这一笔的完整明细
- **单笔明细（点会话行展开）**：
  - 顶部统计 + 「上下文滚雪球」图：每步请求的输入 token 柱状（未命中/缓存命中分色）+ 累计积分折线，一眼看出 token 涨在哪几步
  - 完整流程时间线：每次提问 → 思考 → 调用工具/Skill/MCP（含子代理标记）→ 拿到结果 → 再思考，逐步推进
  - 每步右侧 token 构成小条（未命中输入/缓存命中/思考/输出四色）+ 该步真实积分（免费/预览通道模型标注「不计积分」）
  - 思考原文与工具参数/返回默认折叠，点击展开（默认折叠也顺带保护隐私，截图外发不泄露全文）
- 深浅色主题（记忆偏好）、单文件离线、零外部依赖

## 数据与口径说明

- 数据源：`~/.workbuddy/projects/**/*.jsonl` 中每条记录的 `providerData.rawUsage`（请求级真实 usage，非估算）；深层子代理日志（`subagents/agent-*.jsonl`）自动归属父会话并打「子代理」标记。
- **官方实际积分（主口径，最准）**：日志 `rawUsage.credit` 是平台逐请求回传的真实积分消耗，与 App 账单同源，直接汇总即可，无需估算。免费模型（限时免费期）该字段为 0，属正常。已实测：逐条汇总与按 (messageId, conversationRequestId) 去重汇总结果一致，不存在重复计数。
- **「步骤」= 一次模型请求**：一条带 usage 的记录即一步；`conversationRequestId` 为一次用户指令下的完整 agent 循环（单笔明细里按「第 N 次提问」切段）。
- **标称倍率 ≠ 实际积分率**：倍率只是名义参考。实际每百万 token 积分还受缓存命中、思考 token、输出 token 计价权重影响，账单两者并列展示正是为了让用户自己看懂这笔账。注意网上流传的"积分 = 总 Token ÷ 1M × 倍率"说法刻度偏小数十倍，不要采用。
- **倍率来源（自动三级回退）**：① 生成时实时抓取官方文档《选择模型》页；② 失败则读本 skill 目录下 `multipliers.json` 缓存；③ 再失败用脚本内 `MULT_FALLBACK` 内置表。官方文档表常滞后于 App 内模型列表，脚本会用内置表补齐缺失项（官方值优先）。
- 会话标题三级优先级：① 平台 `ai-title` 记录的 `aiTitle`；② 用户消息提取（先剥 `<system-reminder>` 包装块，取 42 字）；③ 兜底"(无标题会话)"。
- 明细范围：默认嵌入近 30 天会话的完整流程，更早的会话只在清单显示汇总并标「超出回放范围」（点击会看到明确提示，不会没反应）；超长会话明细保留首 300 + 尾 300 个事件（中间标注省略），汇总数字不受影响。

## 注意

- **想"随时看最新账单"？** 客户端左侧导航栏是原生界面，无法加自定义入口（官方无此机制）。标准方案即执行步骤第 5 步：资料库「WorkBuddy积分账单」固定在线页面（每天重导入覆盖新版本，链接不变）+ 每日 09:00 自动化自动刷新同步。用户在 WorkBuddy 左侧菜单点「资料库 → 我的文档 → WorkBuddy积分账单」即为最新数据。若用户需要真正的秒级实时（每次打开都现算），可另行装本地常驻服务（launchd + localhost HTTP），脚本本身不负责这层。
- 与 `token-dashboard` skill 的分工：那个是「总账本」（全局花了多少、按天/按模型/按工作空间汇总），本 skill 是「明细账单」（每个模型/每笔任务花多少、每一步积分去向）。两者数据同源、口径一致，可同时安装，互不依赖。
- 账单内数据完全来自本机日志，不会外发；生成的是本地文件，不会自动上传。唯一联网动作是生成时抓取官方倍率页（失败自动回退缓存/内置表，全程离线也可用）。
- Windows 控制台为 GBK 时脚本已内置 UTF-8 输出保护，若仍乱码不影响 HTML 生成。
- 本 skill 只做本机日志的只读解析与可视化，不修改、不删除任何日志文件。
